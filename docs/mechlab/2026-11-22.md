# The 1.0.49 playtest and the expanded Vulkan renderer

We released the first Core Critical playtest build, 1.0.49-preview, to playtesters. It includes the updated MW3-RE runtime, new controls, and Vulkan work that grew to cover scene capture, GPU lighting, fog, loading, and the full menu presentation path.

## The playtest build

- The launcher opens Controls maximized. It supports mouse side buttons, wheel steps, two- or three-input combinations, mouse headlights, and an MW2 Jump Jets toggle. The updated MW5-style preset uses the middle mouse button to toggle zoom, the wheel to cycle weapons, and direction-plus-Space combinations for jump jets. Existing custom profiles retain their bindings.
- The staged release runtime loaded a file with three extended bindings in a Training run capped at 180 frames and exited normally. Clean installation, upgrade, rollback, and interactive controls still need testing on a separate Windows test PC.
- A separate developer arena can run repeatable bot matches and inspect their logs through top-down and 3D viewers. It stays separate from campaign, Instant Action, and normal multiplayer play.


## Inside the Vulkan renderer

The renderer work spanned the path from the game's draw calls to the final frame. It joined the MW3-RE v1.1.1-based runtime with Core Critical's Vulkan backend and editor compositing. The rollout covered prepared geometry and materials, camera and viewport state, lighting, render-thread pacing, fog, and the menu and HUD.

### Scene data and resource lifetime

A draw can reach the GPU after the game has moved its camera or changed the viewport. The submission path now carries the camera, projection and viewport that belonged to that draw. Batching keeps different views apart. The POM material path also uses the producing camera, which matters for viewing-angle-dependent height sampling. Scene-owned lights are retired on teardown so lights from one mission cannot leak into the next. The render thread still overlaps work with the game thread and keeps at most one presented frame in flight.

### Lighting, materials and effects

The new path brings the stock weapon-emitter catalog and selected effects packs into the same renderer. It carries fixture lights, muzzle flashes and authored mech headlights through native and prepared draws. Model materials receive the appropriate sun shadows and fog. The sky keeps its authored treatment, translucent lasers keep their intended brightness, and the HUD portrait again turns red as a mech takes damage. Water and cloud detail use matching data from selected environment packs. Height mapping is available to eligible, verified materials when the POM path is enabled, with broader POM content and live coverage still under development.

Local lights are grouped into lists for screen tiles. The renderer now prefers GPU-local memory for those lists, reuses the bindings that tell shaders where to read them, and shares a lighting view when multiple models use the same camera. In a focused check, 73 models shared one canonical lighting view. The tests also compared output pixels with a reference. Views that need separate camera data remain separate, and valid extra views can use all admitted lights. A separate fix finishes staged light uploads as the CPU staging budget fills so a busy scene can keep rendering.

### Distance, fog and presentation

The five scenery-distance choices run from the original 800 to 3200. At extended ranges the renderer scales the mission's existing haze and adds an edge band that works regardless of altitude. A radial fade eases opaque scenery out near the selected cutoff as the player turns. Native, prepared and reference draws received corrections so they agree more closely, including prepared mechs in fog and the zoom pass inside its own rectangle. Longer distances increase rendering work, and behavior across missions and hardware still needs playtesting.

The original menu still decides what to draw. Vulkan now presents those commands at output resolution, with the original 4:3 foreground centered over a full-window HD background. The CPU canvas remains available for native reads and for frames the GPU path cannot reproduce. The ripple effect samples a GPU-resident scene snapshot and keeps the original draw order, including text or sprites drawn after the ripple. A bounded RX 9070 menu-hover comparison reduced the 95th-percentile frame time from about 82 ms to 25 ms. That result covers the tested menu interaction on that machine.

### Loading and mission stability

The loader now saves verified pack hashes between launches, keeps the window responsive and preloads normal pages, textures and geometry that used to be prepared during a first turn. Prepared mech skins follow each unit's game-selected livery. A draw-lifetime fix addressed a crash seen when a skin was evicted in C3M3, and the decoded skin cache now defaults to 1 GiB so more of the mission's skins can stay resident. These changes passed focused checks and bounded native runs. The wider playtest is where we will check longer sessions and more hardware combinations.
