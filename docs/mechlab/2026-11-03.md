# Renderer foundations, reliable builds, and the next playtest

Since the October 30 update, work has focused on reproducible native builds, rendering correctness, community-pack contracts, and a targeted repair for the Training-to-menu crash. Launcher and runtime 1.0.46 were published; the next playtest build is being prepared from reviewed main-branch source.

## What changed

- The native host can be rebuilt from committed source with documented, pinned dependencies. An independent second-PC build passed, and the published runtime's source fingerprints match the committed manifest. Original game files and translated game code remain separate local inputs.
- Development-only world-resolution controls can reduce world rendering resolution while retaining output-resolution HUD composition. Ordered surface writes, retained pixels, alpha, depth and reconstructed shadows received focused repairs and bounded native checks. The default remains 100 percent; these controls are not a public launcher setting.
- Authenticated camera history now records frame-completion state and handles recognized load boundaries and surface readbacks. This is groundwork for temporal rendering. FSR upscaling, frame generation and a demonstrated performance improvement are not delivered by this work.
- Optional surface-material contracts now validate height, roughness, reflectivity and metallic metadata for community mech packs. General parallax rendering and the terrain and mech height-map tools remain under review with known integration blockers.
- A targeted native-host repair initializes menu fields before an early callback reads them when returning from Training. Build checks and independent code review passed. Repeated Training-to-main-menu gameplay confirmation, especially on the affected Intel system, remains pending.
- Atlas appearance work demonstrated original and upgraded textures through an imported pack, Mech Lab and bounded Instant Action runs. The appearance PRs remain separate from the release branch; global selection, additional skins, cockpit alignment and broader gameplay coverage are still being worked on.
- Repository work is tracked through issue cards, reviewed feature PRs and separate releases to main. The board now distinguishes implementation, review blockers and pending validation, with explicit next actions.

## What comes next

Prepare and verify the next signed launcher installer and runtime updates before announcing availability. Continue the outstanding Training-return and compatibility playtests. Performance investigation starts with a capture-free baseline and CPU attribution before controlled comparisons; existing measurements do not establish a general speedup. A separate minimal public-source package is being audited to exclude website code, deployment information, private data and original game content before any open-source publication.
